# MinSU Clearance System

A paperless student clearance platform for **Mindoro State University** —
FastAPI + MongoDB backend, React + vanilla-JS SPA frontend.

- Bcrypt password hashing, full audit log, per-clearance audit trail
- Brute-force lockout (5 fails / 15 min → 15-min lock)
- Digital e-signatures (draw / type / saved), printable clearance slip
- Validation on every important action (server + client)

Default admin (auto-seeded on startup):

- **Email:** `admin@minsu.edu.ph`
- **Password:** value of `ADMIN_PASSWORD` env var (default `Admin@MinSU2025`)

## 2. Local development

```bash
# ---- backend ----
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # then edit MONGO_URL / DB_NAME if needed
uvicorn server:app --reload --port 8001

# ---- frontend (new terminal) ----
cd frontend
cp .env.example .env      # then set REACT_APP_BACKEND_URL=http://localhost:8001
yarn install
yarn start
```

Open <http://localhost:3000>.

## 3. Deploy on Render (one-click Blueprint)

This repo ships a `render.yaml` blueprint that provisions **two services** —
one backend and one static frontend.

### Step-by-step

1. **Create a MongoDB Atlas cluster** (free tier is fine)
   → `Database Access` → add a user
   → `Network Access` → allow `0.0.0.0/0`
   → copy the connection string like
   `mongodb+srv://<user>:<pass>@cluster0.mongodb.net/?retryWrites=true&w=majority`

2. **Push this repo to GitHub** (a Save-to-GitHub button is available in the
   Emergent chat input).

3. **In Render** → `New +` → `Blueprint` → connect the GitHub repo.
   Render will detect `render.yaml` and prompt for the values marked
   `sync: false`:

   | Service   | Variable              | Value                                                     |
   |-----------|-----------------------|-----------------------------------------------------------|
   | backend   | `MONGO_URL`           | your MongoDB Atlas connection string                      |
   | backend   | `CORS_ORIGINS`        | leave blank the first time — fill in step 5               |
   | frontend  | `REACT_APP_BACKEND_URL` | leave blank the first time — fill in step 5             |

4. **Click Apply.** Render will:
   - install `backend/requirements.txt` and start
     `uvicorn server:app --host 0.0.0.0 --port $PORT`
   - `yarn build` the frontend and serve `frontend/build/`.

5. **Wire the two services together.** Once both are green:

   - Copy the backend URL, e.g. `https://minsu-clearance-backend.onrender.com`
   - Copy the frontend URL, e.g. `https://minsu-clearance-frontend.onrender.com`
   - Backend → **Environment** → set
     `CORS_ORIGINS = https://minsu-clearance-frontend.onrender.com`
     → **Save & redeploy**.
   - Frontend → **Environment** → set
     `REACT_APP_BACKEND_URL = https://minsu-clearance-backend.onrender.com`
     → **Manual Deploy → Clear build cache & Deploy**.

6. **Log in** to the frontend URL with the default admin credentials
   (`ADMIN_PASSWORD` is auto-generated by Render — check the backend’s
   Environment tab).

### Deploying without the Blueprint

If you prefer to click-through:

- **Backend** — New + → Web Service → Python → root `backend/`
  - Build: `pip install -r requirements.txt`
  - Start: `uvicorn server:app --host 0.0.0.0 --port $PORT`
  - Env vars: `MONGO_URL`, `DB_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`,
    `CORS_ORIGINS`, `PYTHON_VERSION=3.11.9`
- **Frontend** — New + → Static Site → root `frontend/`
  - Build: `yarn install --frozen-lockfile && yarn build`
  - Publish dir: `build`
  - Env vars: `REACT_APP_BACKEND_URL`, `NODE_VERSION=20.11.1`, `CI=false`
  - Rewrites: `/* → /index.html`

## 4. Environment variables reference

### `backend/.env`

| Var             | Required | Description                                                        |
|-----------------|----------|--------------------------------------------------------------------|
| `MONGO_URL`     | ✅       | MongoDB connection URI (Atlas or local)                            |
| `DB_NAME`       | ✅       | Database name (default `minsu_clearance`)                          |
| `ADMIN_EMAIL`   | ⛔ opt   | Default admin email (default `admin@minsu.edu.ph`)                 |
| `ADMIN_PASSWORD`| ⛔ opt   | Default admin password (default `Admin@MinSU2025`)                 |
| `CORS_ORIGINS`  | ⛔ opt   | Comma-separated origins, or `*` (default). Set to your frontend URL for prod. |

### `frontend/.env`

| Var                    | Required | Description                                     |
|------------------------|----------|-------------------------------------------------|
| `REACT_APP_BACKEND_URL`| ✅       | Full base URL of the backend (no trailing `/`)  |

## 5. Verifying the deploy

```bash
BACKEND=https://<your-backend>.onrender.com

curl -s $BACKEND/api/
# → {"message":"MinSU Clearance System API","version":"2.0.0"}

curl -s -X POST $BACKEND/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"admin@minsu.edu.ph","password":"<your ADMIN_PASSWORD>"}'
# → {"success":true,"user":{...,"role":"admin",...}}
```

## 6. Free-tier notes

- Render’s free web services **sleep after ~15 min of inactivity**. The first
  request after sleep can take 30–60 s to boot.
- MongoDB Atlas free tier is limited to 512 MB — fine for a few thousand
  clearances.
